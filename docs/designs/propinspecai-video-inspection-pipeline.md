## Problem Statement

GPM Property Management (850+ single-family rental units, 50+ years in business) runs move-out inspections through Zinspector today: 30+ interior/exterior photos, room and window measurements, a repair list, and wall/floor/carpet condition notes, all hand-entered. The report feeds the rehab quote for the owner and the move-out report to the outgoing tenant, then routes to maintenance for vendor quotes. Each inspection takes 2-3 hours, and Zinspector is described as clunky and limited. PropInspecAI's core idea: the inspector shoots video while narrating damage, measurements, and suggested repairs; AI extracts stills from the video, transcribes the narration, and produces the structured report and rehab quote — no manual re-typing.

## Reference Material

Real Zinspector move-out report reviewed (2026-09-09): "1554 Brest Move Out 9-9-26.pdf," inspected by Chuck Larson, at `C:\Users\chris\projects\PropInspecAI\`.

- **Structure:** per-room/area sections (Attic, Common, Entry, Exterior, Bathroom x2, Bedrooms, Hallway/Stairs, Kitchen, Living Room, Basement, Garage/Parking, Keys/Remotes/Devices) — each a Detail × Condition (NA / Good / Damaged) × Actions × Comment table, followed by a photo gallery per item. Ends with "Additional Comments," a 3-business-day dispute notice, and a signature line.
- **Every photo carries GPS coordinates + a timestamp.** This is real evidentiary/anti-dispute value the current tool already provides — a video-based pipeline must preserve per-frame geolocation and timestamp (from the video's own metadata, applied to each extracted still), not just one location for the whole video, or this is a real regression, not just a nice-to-have.
- **The "Actions" field already exists in Zinspector and is unused** — every row in this report reads "None." Repairs are written as free-text in the shared Comment column instead. This directly supports the core thesis: structured per-fixture data entry is slower than narrating, which is why even a tool that HAS structure doesn't get it filled in.
- **Measurements are not a structured field today** — they appear ad hoc inside Comment text ("5 x 10", "4x7"), inconsistently, only sometimes. PropInspecAI capturing them via narration is not a regression from current practice — it's an upgrade path over what's inconsistently done today.
- **No pricing/quote data appears anywhere in this report** — confirms the quoting step is a fully separate, later process (consistent with the "manual/spreadsheet, no API" answer above).

## Constraints

- Video-based capture must work reliably on-site with variable lighting, phone cameras, and inspector narration quality — accuracy of extracted measurements and damage assessment is the technical crux.
- **Working assumption (unconfirmed):** measurements are spoken by the inspector ("this room is 12 by 14") and captured via transcription, not visually estimated by AI from the video frame — the latter is a materially harder computer-vision problem and would change the effort estimate for Approach A significantly. Confirm this before scoping the build. (See Reference Material: today's practice is inconsistent ad hoc measurement capture, so this is not a regression either way.)
- **Per-frame geolocation/timestamp must be preserved.** The current Zinspector report stamps GPS + timestamp on every individual photo — real evidentiary value for dispute protection. Extracted video stills need the same per-frame metadata, not one location for the whole video.
- Output must integrate with GPM's existing quoting/vendor software (system not yet named in this session — needs to be identified before build).
- Report must satisfy two distinct audiences from one pipeline: the owner-facing rehab quote and the tenant-facing move-out/deposit disposition report — these likely have different format and legal-disclosure requirements.
- **AI-generated reports need a human review/approval gate before they reach a tenant or owner.** Given the acknowledged legal-disclosure exposure on deposit dispositions, nothing should go out unreviewed — this is a QA step, not optional polish.
- **PROVISIONAL architecture decisions (plan-eng-review 2026-09-09, cross-model tension resolved):** the three items below were decided in this review session but are explicitly PROVISIONAL — re-confirm only after The Assignment's hand-test succeeds. The outside-voice review correctly flagged that locking in pipeline architecture before validating the one open technical risk (can AI reliably read measurements/damage from real footage) risks deciding the wrong problem. None of this blocks starting The Assignment.
  - **Extraction architecture:** multi-step pipeline — extract stills and transcribe audio separately, then a schema-enforced structuring step (tool-use, not raw-JSON prompting) — not a single native-video-model call. Matches 2026 best practice and gives the human review gate a natural seam, between "extract" and "structure."
  - **Data retention:** raw inspection videos and generated reports retained indefinitely — no auto-deletion policy. Access scope (who can view raw video vs. just the finished report) still worth restricting to the inspection/maintenance chain by default. Cross-model review flagged a subpoena/discovery exposure concern on indefinite retention of in-unit recordings; user's call: not a concern for GPM's situation, proceed as decided.
  - **Ingestion trigger:** ~~Google Drive push notifications~~ **reversed after cross-model review:** polling every 10-15 min. Two independent reviews agreed push-notification webhooks solve a latency problem that doesn't exist — the mandatory human review gate means nothing downstream is time-sensitive, so near-instant trigger buys no real benefit against real webhook-maintenance cost (channel renewal, endpoint infra).

## Premises

1. **(Revised)** The AI video-to-report extraction itself (photos, transcript, damage list) is achievable with off-the-shelf multimodal AI models and is not, by itself, a defensible moat. Landscape scan found AnyInspect (engineering/building-inspection focused, not rental PM), PropertyInspection.ai (no live product found — "Express Interest" CTA only, likely pre-launch), and zInspector's own "zAssistant" feature all claiming some version of this. None has executed it well for single-family rental property management specifically, which leaves room to be first — but the extraction step alone won't keep a competitor out.
2. **Agreed.** The real differentiated wedge is eliminating the rekey-into-quoting-software step and the senior-level manual rehab pricing step — going straight from inspection video to a priced, vendor-ready quote. This is the part no competitor found in this session's landscape scan advertises doing.
3. **Agreed.** Zero demand has been validated outside GPM. Every specific piece of evidence in this session (cost data, named stakeholders, urgency) is internal. Before committing further engineering to a sellable Propmind AI product, the fastest real test is putting actual pipeline output in front of 2-3 outside PM operators and seeing if they'd pay — not assuming the sale.

## Approaches Considered

### Approach A: Minimal viable — GPM-only pipeline tool
Build the smallest possible video → structured report → draft rehab quote pipeline for GPM's own use. Effort: S-M. Risk: Low-Medium.
- Reuses GPM's existing quoting software and vendor list; existing tenant/owner report formats.
- Pros: fastest way to capture the already-quantified $44,200/yr internal cost; proves the hardest technical risk (reliable extraction from real GPM footage) fast.
- Cons: produces no evidence, by itself, that anyone outside GPM would pay.

### Approach B: Ideal architecture — full multi-tenant Propmind AI platform
Build a sellable SaaS from day one: configurable report templates per customer, per-tenant data isolation, integrations with common PM/quoting software (AppFolio, Buildium, Yardi, RentManager, etc.), billing. Effort: L-XL. Risk: High.
- Pros: if demand is real, this is the actual product; positions Propmind AI to onboard other PM companies immediately.
- Cons: commits months of engineering before a single dollar or explicit "yes" exists from outside GPM — the exact "build the platform before anyone can use it" trap. **Rejected for now** — sequenced too early against Premise 3.

### Approach C: Creative/lateral — concierge validation with outside PM operators
Skip building a product for outsiders. Hand-process real move-out videos for 2-3 outside PM operators (drawing on the user's existing industry relationships), for free or a nominal fee, and see whether they come back wanting more or offer to pay recurring.
- Pros: tests Premise 3 for near-zero incremental cost; turns "I'm confident it's marketable" into an actual yes/no.
- Cons: feels more like a hand-run pilot than a product on paper; doesn't produce reusable multi-tenant infrastructure by itself.
