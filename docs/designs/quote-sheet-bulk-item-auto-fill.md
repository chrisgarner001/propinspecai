## Problem Statement

Chris proposed a broad "Auto Process Quote" feature: one button that would auto-fill bulk
materials into matching line items, assign vendors from comment patterns and past jobs,
estimate labor hours from historical data, pull SKU/pricing from a "Cost Book," and keep
improving those suggestions over time as the system is used across the company.

## Status Quo

Today the reviewer (Jessica) fills Supplier/SKU, vendor assignment, and labor hours by hand,
per line item, from memory — no cross-reference to a price list, past quote, or prior job.
Confirmed manual/from-memory with no existing workaround tool.

## Target User & Narrowest Wedge

Target user: the Quote Sheet reviewer (Jessica), on real, owner-facing quotes for GPM.
Narrowest wedge confirmed by Chris: bulk-item auto-fill only (the light-bulb example) —
lowest risk, no new data source needed, concrete acceptance test already given (two
"Attic Light Bulb" rows on the 11020 Brookwood inspection).

## Constraints

- Real financial document — auto-filled data that's wrong has real trust/cost consequences,
  unlike a cosmetic UI change.
- A Cost Book *does* already exist (`cost_book_gpm_labor`, `cost_book_materials`,
  `cost_book_vendor_estimates` + a CRUD admin page at `app/cost-book/`) — correcting an
  earlier assumption in this session. But it's essentially empty in production (1 test
  row per table, e.g. "Light Fixture (2-bulb flush mount)" / SKU 1001102102), so it isn't a
  usable data source for auto-fill yet. Populating it with real data would unlock the
  Cost Book pricing piece without needing a "historical learning" system at all — worth
  doing before that piece gets scoped.
- No vendor-assignment or labor-hours historical-outcomes data is captured anywhere today
  (no "was this choice right" signal) — that piece genuinely doesn't exist yet.
- Confirmed via observation: item naming is fairly consistent (small repeated vocabulary of
  rooms + fixture types), not free-form — this is what makes a deterministic heuristic viable
  instead of requiring an AI call.

## Premises

1. The full 4-part vision is a multi-quarter roadmap, not one button — vendor assignment,
   labor-hour estimation, and Cost Book pricing each need a historical dataset that doesn't
   exist yet.
2. Given consistent naming and low-stakes fields, a deterministic keyword-matching heuristic
   is sufficient for bulk-fill — no Gemini/AI call needed, no "master prompt" update required
   for this piece.
3. Auto-fill must only ever write into fields that are currently blank on the line item —
   never overwrite a value the reviewer already entered.
4. "Continually learning across the company" requires an outcomes feedback loop that does not
   exist yet. Real, but out of scope for this wedge — deferred, not delivered dishonestly.

All four agreed by Chris without revision.

## Approaches Considered

### Approach A: Silent auto-fill on add
Writes matches directly the moment a Bulk Material is added, no confirmation step. Fastest,
matches the original wording literally, but a wrong match is easy to miss since nothing
flags that a write happened.

### Approach B: Suggest-and-confirm banner (chosen)
Adding a Bulk Material computes keyword matches against blank-Supplier/SKU line items in the
same inspection and shows them in an on-page "Matched N items — Apply / Skip" banner before
anything is written.

### Approach C: Live link instead of copy
Matched line items get tagged "covered by [bulk item]" instead of copying supplier/SKU text;
PDF export resolves the link at generation time so edits to the bulk item propagate
automatically. Rejected for v1: needs a new join table and touches Materials Order List PDF
logic — bigger than the agreed wedge.

## Recommended Approach

**B — Suggest-and-confirm.** Delivers on "be smart enough to auto-fill" while keeping the one
cheap safeguard a real financial document deserves (visible before it's written), and the same
"candidate + confirm" pattern extends cleanly to vendor/labor suggestions later without a
redesign.

## Matching Algorithm (v1) — verified against real data

- Computed at page-render time (Quote Sheet server component), not on insert — re-evaluated
  each load until the reviewer applies or dismisses it (`inspection_bulk_materials.matches_reviewed`).
- Words come from the bulk material's **SKU field only** — not supplier, not notes. First
  draft used supplier+sku+notes combined and was verified against the real 11020 Brookwood
  data (`supplier: "Home Depot"`, `sku: "Light Bulbs"`, `notes: "light bulbs for
  replacement"`) *before* shipping: it produced **zero** matches, because "Home Depot" and
  "replacement" never appear in an item name. Supplier is a generic store name; notes is
  freeform text. SKU is the only field that's consistently a short "what this actually is"
  descriptor, matching the "fairly consistent naming" Chris observed.
- Trailing "s" is stripped before comparing (e.g. "Bulbs" → "bulb") so "Light Bulbs" matches
  "Attic Light Bulb".
- Candidate line items: same inspection, not removed from the sheet, and **both** `supplier`
  and `sku` currently blank.
- Match rule: ALL stemmed words from the SKU must appear (case-insensitive substring) in the
  item name. AND, not OR — verified this produces exactly the 2 "Attic Light Bulb" rows for
  the real light-bulb bulk item, and zero (not a wrong guess) for a "Caulk - White" bulk item
  against "Toilet Base Caulking" — a known, accepted limitation: a SKU with a qualifier word
  like a color will under-match rather than risk a wrong auto-fill. Under-matching just means
  the reviewer fills that one in manually, same as today.
- No AI call.

## Open Questions

- None blocking. Future phases (vendor assignment, labor-hour estimation, Cost Book pricing,
  the actual self-learning/outcomes loop) are explicitly deferred and would each need their
  own scoping session once the underlying historical data exists.

## Success Criteria

- Adding a "light bulb" bulk item on the 11020 Brookwood inspection surfaces a confirm banner
  naming the 2 "Attic Light Bulb" rows; clicking Apply fills their Supplier/SKU/Qty from the
  bulk item and does not touch any line item that already had a Supplier/SKU value.

## The Assignment

Ship the wedge (Approach B) and validate it live against the 11020 Brookwood inspection with
the actual light-bulb bulk item — the concrete acceptance test Chris already gave. If it
produces exactly the 2 expected matches with zero false positives on a handful of other real
inspections, the keyword-AND heuristic is validated well enough to reuse for the vendor/labor
wedges later.
